14 · IntelliJ IDEA and VS Code: read, test, debug, deploy

An IDE is an editor/debugger and a place to run the build tools. Deployment should still use reproducible scripts and reviewed infrastructure, not undocumented IDE state. Start debugging the pure calculation, then attach to a containerized activity process for integration behavior.

When to use it

  • Fast unit-test feedback, code navigation and traceable changes.
  • Remote debugging of a local container while its actual Kafka/AWS connections remain inside Docker.
  • Avoid adding workstation hosts-file entries or public broker access just to make native IDE networking work.

Create through the AWS console / IDE

  1. IntelliJ: File → Open application/pom.xml as a Maven project. Set Project SDK and Maven runner to Java 21. Reload Maven, open AccountingTest, and run/debug a test with a breakpoint in Accounting.calculate.
  2. IntelliJ: create a Remote JVM Debug configuration for localhost:5005 after starting the local debug override. Do not expose that debug port in AWS.
  3. VS Code: open EventFlow.code-workspace. Install the Java extension pack; AWS Toolkit and Docker tooling are optional helpers. Set the Java 21 runtime and run tests from Testing.
  4. VS Code: use the provided attach launch configuration for localhost:5005. Put a breakpoint in Accounting.calculate and submit a small test through the real GUI.
  5. In either IDE terminal, run Maven, build the image, push to ECR and apply the reviewed manifests. Treat CI as the authoritative enterprise release path.

Test this component before continuing

Inspect principal, rate, event factor and the rounded amount at a breakpoint. Verify exactly which service role is paused. Resume promptly: long pauses can exceed Kafka poll intervals or workflow heartbeats and cause safe replay/rebalance.

Exit criterion

A reproducible breakpoint exercise using real infrastructure, plus passing unit tests. Debug ports are loopback-only and absent from normal/AWS manifests.

package com.eventflow;
import com.eventflow.shared.*;
import com.eventflow.mock.MockGetData;
import com.eventflow.adapter.EventAdapter;
import com.eventflow.coordinator.BatchCoordinator;
import com.eventflow.sourcing.*;
import com.eventflow.activity.ActivityService;
import com.eventflow.web.ConsoleServer;

/** One image, explicit service roles. Each role runs in its own container/pod. */
public final class Main {
    public static void main(String[] args)throws Exception{
        String role=Json.env("SERVICE_ROLE","console");Json.log("startup","Starting "+role);
        if(role.equals("mock-source")){MockGetData.run();return;}
        // Startup ordering: resources must exist before any consumer runs.
        for(int attempt=0;;attempt++){try{Store.config();break;}catch(Exception e){if(attempt>=90)throw e;Thread.sleep(2000);}}
        switch(role){
            case "console" -> {
                Kafka.topics(6);
                new Thread(BatchCoordinator::run,"batch-coordinator").start();
                new Thread(()->WorkflowWorker.poll("eventflow-await-accounting",WorkflowWorker::awaitAccounting),"workflow-completion").start();
                ConsoleServer.run();
            }
            case "adapter" -> EventAdapter.run();
            case "sourcing" -> SourcingService.run();
            case "activity" -> ActivityService.run();
            default -> throw new IllegalArgumentException("Unknown service role: "+role);
        }
    }
}

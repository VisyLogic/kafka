15 · GUI and S3 file trigger: your application entry point

A small request JSON describes event type, level, accounting date and test volume. The GUI can save it to the configured S3 bucket, read it back, validate it, and start the normal event-generation/Kafka path. This is an explicit upload-and-start operation, not an automatic S3 notification.

When to use it

  • Business-user batch requests, reproducible training scenarios and source provenance.
  • The same file may be uploaded in the S3 console and imported by key.
  • Each click intentionally creates a new test run; this teaching trigger does not deduplicate file submissions or provide a transactional outbox.

Create through the AWS console / IDE

  1. Open EventFlow → New volume test → Start from an S3 request file. Download the sample JSON.
  2. Choose an accounting date and modest volume. Select the JSON file, review the preview, then click Upload to S3 & start processing.
  3. Inspect Run JSON: trigger.type is S3_FILE and includes the bucket, object key, object version/ETag and filename. Events inherit this provenance.
  4. Alternative: S3 console → configured bucket → upload under event-requests/. Paste the key into the GUI and select Start from this S3 object.
  5. Observe that a console-only S3 upload produces no run until you explicitly start it. An automatic S3→EventBridge/SQS/Lambda adapter is an advanced optional design, not silently installed here.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.

Test this component before continuing

Verify the object exists in S3, then the run appears in the GUI, events enter Kafka topic 1, a batch starts, and BE/AR counts reconcile. Try an invalid date, over-limit volume and object key outside event-requests/: each must be rejected before starting accounting.

Exit criterion

One explicit run with S3 provenance. Uploading an ordinary JSON descriptor does not place full loan datasets in S3. The source still streams gRPC directly into Kafka.

package com.eventflow.web;

import com.eventflow.shared.Json;
import java.time.Instant;
import java.util.*;
import java.util.function.BiFunction;

/** Explicit upload-and-start trigger. Uploading in the S3 console alone does not run accounting. */
public final class S3EventTrigger {
    public interface Artifacts {
        void save(String key,Map<String,Object> request);
        Map<String,Object> load(String key);
        default Map<String,Object> metadata(){return Map.of();}
    }
    private final Artifacts artifacts;
    private final BiFunction<Map<String,Object>,Map<String,Object>,Map<String,Object>> start;
    private final String bucket;
    private final int maxLoans;
    public S3EventTrigger(Artifacts artifacts,BiFunction<Map<String,Object>,Map<String,Object>,Map<String,Object>> start,String bucket,int maxLoans){
        this.artifacts=artifacts;this.start=start;this.bucket=bucket;this.maxLoans=maxLoans;
    }
    @SuppressWarnings("unchecked") public Map<String,Object> upload(Map<String,Object> body){
        String name=Json.text(body,"fileName");
        if(!name.matches("(?i)[a-z0-9_. -]{1,120}\\.json"))throw new IllegalArgumentException("Choose a JSON filename without path separators");
        if(!(body.get("request") instanceof Map<?,?>))throw new IllegalArgumentException("request must be a JSON object");
        var request=(Map<String,Object>)body.get("request");validate(request);
        String key="event-requests/"+UUID.randomUUID()+"/"+name;
        artifacts.save(key,request);
        return startStored(key,name);
    }
    public Map<String,Object> importObject(String key){
        if(!key.startsWith("event-requests/")||key.contains("..")||!key.endsWith(".json")||key.length()>400)
            throw new IllegalArgumentException("Use a JSON object key under event-requests/ in the configured bucket");
        return startStored(key,key.substring(key.lastIndexOf('/')+1));
    }
    private Map<String,Object> startStored(String key,String name){
        var stored=artifacts.load(key);validate(stored);
        var origin=new LinkedHashMap<String,Object>(Map.of("type","S3_FILE","bucket",bucket,"objectKey",key,"fileName",name,"startedAt",Instant.now().toString()));
        for(String field:List.of("objectVersionId","objectETag"))if(artifacts.metadata().containsKey(field))origin.put(field,artifacts.metadata().get(field));
        var result=new LinkedHashMap<>(start.apply(stored,origin));result.put("trigger",origin);return result;
    }
    private void validate(Map<String,Object> request){
        var allowed=Set.of("totalLoans","poolSize","level","eventType","accountingDate");
        if(!allowed.containsAll(request.keySet()))throw new IllegalArgumentException("Request files accept test settings only; remove unknown fields");
        for(String field:allowed)
            if(!request.containsKey(field))throw new IllegalArgumentException("Request file is missing "+field);
        RunRequest.parse(request,maxLoans);
    }
}

Explain and investigate

Design a future automatic S3 notification trigger. Where would you deduplicate bucket/key/version deliveries, and how would you recover a crash between accepting the file and publishing its Kafka events?

What to record in your lab notebook
  • Account/region, resource IDs and chosen provisioning method.
  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

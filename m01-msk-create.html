M01 · Prepare the network and create an MSK cluster

Build a separate AWS sandbox for hands-on MSK learning. Amazon MSK hosts the brokers; the Java producer/consumer runs on a private VPC-connected EC2 client so EKS is not a prerequisite. Use either the Console path or the supplied CloudFormation path. This lab creates billable MSK/EC2 resources and may use an existing NAT gateway; inspect the change set before execution. Opening the course creates nothing.

When to use it

  • Learn managed Kafka independently of the complete finance platform.
  • Understand broker subnets, Availability Zones and private client access.
  • Compare manual setup with a reproducible infrastructure definition.

Create through the AWS console / IDE

  1. In the AWS Console select a sandbox account and region. In VPC, identify one VPC with DNS resolution/support enabled, two private subnets in distinct Availability Zones and a client subnet with outbound NAT. They must be in the same VPC. If starting from scratch, follow main lesson 03 and its network.yaml first; record the output IDs.
  2. Choose a provisioning path. For CloudFormation: Create stack → Upload template → labs/msk-hands-on/msk-lab.yaml. Set the VPC, two broker subnets and client subnet. Review IAM/resource creation and costs before creating it. It supplies the security groups, client role, EC2 and optional SQS lab too; do not recreate them manually.
  3. Manual alternative: EC2 → Security Groups. Create msk-learning-client with no inbound rules; create msk-learning-brokers allowing TCP 9098 from the client security group and broker-to-broker traffic from itself. Keep outbound connectivity for client downloads and AWS APIs. Follow M02 for the IAM role and client.
  4. MSK → Create cluster → Custom create → Provisioned → Standard brokers. Name it msk-learning, choose a currently supported Kafka version, kafka.m5.large if supported in your region, two AZs and one broker per AZ (two total), with the two private subnets and broker security group. Use a small supported storage size, for example 10 GiB.
  5. Enable IAM access control, disable unauthenticated access, enable TLS for client traffic and encryption in-cluster. Use private connectivity. Create the cluster and wait until ACTIVE. Capture cluster ARN and the IAM bootstrap broker string from View client information. Version/instance choices can vary; select supported values rather than changing the production application.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.
Command / example
# Bash / CloudShell: infrastructure control plane, not Kafka data-plane access.
aws sts get-caller-identity
aws kafka list-kafka-versions
# Run from the extracted course folder; replace subnet and VPC IDs.
aws cloudformation validate-template --template-body file://labs/msk-hands-on/msk-lab.yaml
aws cloudformation deploy --stack-name msk-learning-lab --template-file labs/msk-hands-on/msk-lab.yaml --capabilities CAPABILITY_IAM --parameter-overrides VpcId=vpc-REPLACE BrokerSubnetA=subnet-A BrokerSubnetB=subnet-B ClientSubnet=subnet-CLIENT KafkaVersion=3.9.x --no-execute-changeset
aws cloudformation list-change-sets --stack-name msk-learning-lab
# After reviewing the actual change-set name and resource/cost impact:
aws cloudformation execute-change-set --stack-name msk-learning-lab --change-set-name YOUR_CHANGE_SET
aws cloudformation wait stack-create-complete --stack-name msk-learning-lab
aws cloudformation describe-stacks --stack-name msk-learning-lab --query "Stacks[0].Outputs"
# Use the ClusterArn output:
aws kafka describe-cluster --cluster-arn YOUR_CLUSTER_ARN --query ClusterInfo.State
aws kafka get-bootstrap-brokers --cluster-arn YOUR_CLUSTER_ARN --query BootstrapBrokerStringSaslIam --output text

Test this component before continuing

Confirm the two subnets have different AZs, cluster state is ACTIVE, and IAM bootstrap addresses end in :9098. Record the stack outputs or equivalent manual resource IDs. This checks provisioning, not whether the Java client can publish yet.

Exit criterion

A private IAM-enabled MSK cluster exists in the sandbox, and you have documented how an authorized client will reach its brokers. No EventFlow topics or resources have been altered.

AWSTemplateFormatVersion: '2010-09-09'
Description: Separate MSK learning lab. Two private brokers, SSM Java client and optional SQS exercise. Uses an existing VPC with NAT/SSM connectivity.
Parameters:
  VpcId: {Type: 'AWS::EC2::VPC::Id'}
  BrokerSubnetA: {Type: 'AWS::EC2::Subnet::Id'}
  BrokerSubnetB: {Type: 'AWS::EC2::Subnet::Id', Description: Different Availability Zone from BrokerSubnetA}
  ClientSubnet: {Type: 'AWS::EC2::Subnet::Id', Description: Same VPC with outbound NAT for SSM, package installs and downloads}
  KafkaVersion: {Type: String, Default: 3.9.x, Description: Select a supported Standard broker version in this region}
  ClientAmi:
    Type: 'AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>'
    Default: /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64
Resources:
  ClientSG:
    Type: AWS::EC2::SecurityGroup
    Properties: {GroupDescription: MSK lab client - no inbound ports, VpcId: !Ref VpcId}
  BrokerSG:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupDescription: Private IAM Kafka from lab client
      VpcId: !Ref VpcId
      SecurityGroupIngress:
        - {IpProtocol: tcp, FromPort: 9098, ToPort: 9098, SourceSecurityGroupId: !Ref ClientSG}
  BrokerInternal:
    Type: AWS::EC2::SecurityGroupIngress
    Properties: {GroupId: !Ref BrokerSG, SourceSecurityGroupId: !Ref BrokerSG, IpProtocol: '-1'}
  Brokers:
    Type: AWS::MSK::Cluster
    Properties:
      ClusterName: msk-learning
      KafkaVersion: !Ref KafkaVersion
      NumberOfBrokerNodes: 2
      BrokerNodeGroupInfo:
        InstanceType: kafka.m5.large
        ClientSubnets: [!Ref BrokerSubnetA, !Ref BrokerSubnetB]
        SecurityGroups: [!Ref BrokerSG]
        StorageInfo: {EBSStorageInfo: {VolumeSize: 10}}
      ClientAuthentication: {Sasl: {Iam: {Enabled: true}}, Unauthenticated: {Enabled: false}}
      EncryptionInfo: {EncryptionInTransit: {ClientBroker: TLS, InCluster: true}}
  DeadLetters:
    Type: AWS::SQS::Queue
    Properties: {MessageRetentionPeriod: 1209600, SqsManagedSseEnabled: true}
  Queue:
    Type: AWS::SQS::Queue
    Properties:
      VisibilityTimeout: 60
      SqsManagedSseEnabled: true
      RedrivePolicy: {deadLetterTargetArn: !GetAtt DeadLetters.Arn, maxReceiveCount: 3}
  ClientRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement: [{Effect: Allow, Principal: {Service: ec2.amazonaws.com}, Action: 'sts:AssumeRole'}]
      ManagedPolicyArns: [arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore]
      Policies:
        - PolicyName: LabOnly
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action: ['kafka-cluster:Connect', 'kafka-cluster:DescribeCluster', 'kafka-cluster:WriteDataIdempotently']
                Resource: !Ref Brokers
              - Effect: Allow
                Action: ['kafka-cluster:CreateTopic', 'kafka-cluster:DescribeTopic', 'kafka-cluster:ReadData', 'kafka-cluster:WriteData']
                Resource: !Sub arn:${AWS::Partition}:kafka:${AWS::Region}:${AWS::AccountId}:topic/msk-learning/*/learning.msk.*
              - Effect: Allow
                Action: ['kafka-cluster:DescribeGroup', 'kafka-cluster:AlterGroup']
                Resource: !Sub arn:${AWS::Partition}:kafka:${AWS::Region}:${AWS::AccountId}:group/msk-learning/*/msk-learning-*
              - Effect: Allow
                Action: ['sqs:SendMessage', 'sqs:ReceiveMessage', 'sqs:DeleteMessage', 'sqs:GetQueueAttributes']
                Resource: !GetAtt Queue.Arn
  ClientProfile:
    Type: AWS::IAM::InstanceProfile
    Properties: {Roles: [!Ref ClientRole]}
  Client:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: !Ref ClientAmi
      InstanceType: t3.small
      SubnetId: !Ref ClientSubnet
      SecurityGroupIds: [!Ref ClientSG]
      IamInstanceProfile: !Ref ClientProfile
      MetadataOptions: {HttpTokens: required, HttpEndpoint: enabled}
      Tags: [{Key: Name, Value: msk-learning-client}]
Outputs:
  ClusterArn: {Value: !Ref Brokers}
  ClientInstance: {Value: !Ref Client}
  ClientRole: {Value: !Ref ClientRole}
  ClientSecurityGroup: {Value: !Ref ClientSG}
  BrokerSecurityGroup: {Value: !Ref BrokerSG}
  QueueUrl: {Value: !Ref Queue}
  QueueArn: {Value: !GetAtt Queue.Arn}

Explain and investigate

Why is ACTIVE insufficient evidence of a working Kafka application? Identify the remaining client identity, network and topic checks. In this two-replica lab, min.insync.replicas=2 blocks writes if a replica becomes unavailable; discuss a three-AZ production alternative.

What to record in your lab notebook
  • Account/region, resource IDs and chosen provisioning method.
  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

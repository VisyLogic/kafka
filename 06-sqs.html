06 · SQS buffering, visibility and the ingress DLQ

The adapter commits its Kafka progress after SQS accepts an event. The batch coordinator deletes the SQS message only after durable acceptance into DynamoDB. SQS is an event buffer; it does not wait until 1,000 business events have accumulated.

When to use it

  • Decouple request intake from work, smooth bursts and retry unacknowledged messages.
  • Visibility timeout is a temporary delivery lease, not permanent ownership.
  • The ingress DLQ contains repeated event delivery failures, not failed accounting records.

Create through the AWS console / IDE

  1. SQS → Create queue → Standard. First create eventflow-ingress-dlq with 14-day retention.
  2. Create eventflow-ingress with 120-second visibility, 14-day retention, and a redrive policy pointing to the DLQ after five receives.
  3. Use a separate eventflow-lab-queue for Send/Receive/Delete exercises so a placeholder message cannot poison the real accounting pipeline.
  4. Observe that Receive does not delete a message. After visibility expires it can be received again unless you delete it with the latest receipt handle.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.

Test this component before continuing

Receive once without deleting; wait 15 seconds and receive again. Delete with the new receipt handle. For the application queue, inspect the RedrivePolicy rather than sending an invalid test body.

Exit criterion

The lab message redelivers until deleted. Real ingress has the expected DLQ ARN and receive-count policy. Accounting exceptions remain database outcomes.

package com.eventflow.adapter;
import com.eventflow.shared.*;
import java.time.Duration;

/** Kafka offset moves only after SQS accepts the event. Redelivery is safe downstream. */
public final class EventAdapter {
    public static void run(){
        try(var consumer=Kafka.consumer("eventflow-adapter",Kafka.EVENTS)){
            String queue=Aws.queue();
            while(true){
                var records=consumer.poll(Duration.ofSeconds(1));
                for(var record:records){
                    // Do not skip a failed record and commit later offsets in its partition.
                    while(true){try{Aws.SQS.sendMessage(b->b.queueUrl(queue).messageBody(record.value()));break;}
                        catch(Exception e){Json.log("adapter",e.toString());sleep(2000);}}
                }if(!records.isEmpty())consumer.commitSync();
            }
        }
    }
    private static void sleep(long ms){try{Thread.sleep(ms);}catch(InterruptedException e){Thread.currentThread().interrupt();throw new RuntimeException(e);}}
}

21 · Readiness assessment and next engineering exercises

Use the course to develop practical competence, then demonstrate it through independent operation and tradeoff analysis. Reading a document alone does not establish SME status. The final assessment asks you to build, explain, diagnose and recover without copying unexplained commands.

When to use it

  • A portfolio of evidence: diagrams, scripts, test output and failure reports.
  • A design review explaining where guarantees end and which production controls remain.
  • A basis for deeper AWS networking, Kafka operations, Kubernetes and financial domain training.

Create through the AWS console / IDE

  1. Recreate a clean sandbox using one provisioning method. Record every resource owner and dependency.
  2. Demonstrate console and CLI read operations for each AWS service, plus at least one controlled create/update exercise.
  3. Debug one Java calculation from IntelliJ or VS Code and explain the source-to-target identity chain.
  4. Upload an S3 request file and independently reconcile its complete accounting output.
  5. Demonstrate a safe restart, explain Kafka offsets versus S3 cursors, and review a change set and rollback scenario.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.

What to record in your lab notebook
  • Account/region, resource IDs and chosen provisioning method.
  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

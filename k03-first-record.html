K03 · Create a topic, publish and read records

A Kafka record has a key, value, timestamp and optional headers. For this lab the value is a small JSON event. Kafka stores bytes; it does not validate your JSON business contract automatically. Create an explicit topic rather than relying on automatic creation. Use a loan identifier as the lab key to discuss ordering later.

When to use it

  • Publish settled and payoff facts.
  • Learn command-line tools before writing SDK code.
  • Design event envelopes with eventId, schemaVersion, eventType, entityId and accountingDate. Production contracts need validation and evolution policies.

Create through the AWS console / IDE

  1. Create learning.loan-events with three partitions and replication factor one. This factor is only appropriate for this single-broker lab.
  2. Start the console producer with key parsing. Paste the two example lines shown after the command, then press Ctrl+C. The text before the first | is the key; the rest is the JSON value.
  3. Run the console consumer and check both keys and JSON values. Across partitions, output order can differ from input order.
  4. Use a second key for another loan, and another eventId for a second event on the same loan. Retain identity across delivery retries.
  5. The sample schema is a lab contract, not the full EventFlow production-input format. Never paste these records into the actual accounting topics.

Test this component before continuing

Find both event IDs in the consumer output. Record partition and offset for each. Rerunning the consumer without a fixed group can read them again; reading did not remove them.

package com.eventflow.tools;

import com.eventflow.shared.*;
import java.time.Duration;
import java.util.*;
import org.apache.kafka.clients.admin.*;
import org.apache.kafka.clients.producer.ProducerRecord;

/** A separate lab topic tests the data plane without injecting fake accounting events. */
public final class KafkaProbe {
    public static void main(String[] args)throws Exception{
        String topic="eventflow.lab",marker="probe-"+UUID.randomUUID();
        try(var admin=Admin.create(Kafka.properties())){
            if(!admin.listTopics().names().get().contains(topic))
                admin.createTopics(List.of(new NewTopic(topic,1,Short.parseShort(Json.env("KAFKA_REPLICATION_FACTOR","1"))))).all().get();
        }
        try(var producer=Kafka.producer();var consumer=Kafka.consumer("eventflow-lab-check-"+UUID.randomUUID(),topic)){
            producer.send(new ProducerRecord<>(topic,marker,marker)).get();
            long deadline=System.nanoTime()+Duration.ofSeconds(45).toNanos();
            while(System.nanoTime()<deadline){
                for(var record:consumer.poll(Duration.ofSeconds(1)))if(record.value().equals(marker)){
                    consumer.commitSync();System.out.println("PASS: produced, consumed and committed lab marker on "+topic);return;
                }
            }
        }throw new IllegalStateException("Kafka probe timed out; check listeners, DNS, routes, authentication and permissions");
    }
}

Explain and investigate

Change one JSON field to an unexpected type. Kafka can still accept its bytes; which application component should reject or quarantine it?

What to record in your lab notebook
  • Account/region, resource IDs and chosen provisioning method.
  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

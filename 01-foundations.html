01 · Workstation, account and learning path

Build a controlled learning environment before creating resources. Follow one provisioning path per account/region: console OR CLI OR CloudFormation. Repeating all three against the same resource names creates ownership conflicts. Manual creation teaches the APIs; the enterprise track makes reviewed CloudFormation the source of truth.

When to use it

  • A development account isolates experiments from financial production data.
  • AWS CLI and CloudShell operate the control plane; private Kafka brokers require a client inside the VPC.
  • LocalStack is a local AWS API emulator; Docker hosts it and the Java processes. Offline HTML is documentation, not an AWS emulator.

Create through the AWS console / IDE

  1. Sign into a dedicated development account using your organization’s IAM Identity Center role. Do not use root for application development.
  2. Choose one region, for example us-east-1, and record it for every lesson. Create a budget/owner tag and agree the allowed test sizes.
  3. Open CloudShell for Bash CLI examples. Its normal public environment cannot reach a private MSK broker; use EKS exec or an approved VPC-connected client for Kafka tests.
  4. Install Docker Desktop, Java 21, Maven, AWS CLI v2, kubectl and Helm on the workstation. Open EventFlow.code-workspace or application/pom.xml in the IDE.
  5. Use this course folder as the working directory for commands referring to examples/. Replace all ACCOUNT_ID, ROLE_ARN, VPC_ID and similar placeholders before running them.

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.

Test this component before continuing

Confirm the account ID and region are the intended sandbox. Build the Java tests without deploying AWS resources: from the project application/ folder run mvn test. Open index.html directly in a browser and disconnect networking: all lessons and diagrams must still be readable.

Exit criterion

An intended sandbox identity; Java 21; a working Docker engine; fourteen Java tests after this update; no cloud infrastructure is created by opening this HTML.

Explain and investigate

Explain why a working AWS CLI login does not prove that your laptop can reach a private Kafka broker.

What to record in your lab notebook
  • Account/region, resource IDs and chosen provisioning method.
  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

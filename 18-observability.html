18 · CloudWatch, CloudTrail and operational evidence

The application emits structured stdout logs. In EKS, a log collector/add-on must ship those logs to CloudWatch; stdout does not configure centralized monitoring automatically. Native SQS/DynamoDB metrics and application reconciliation measure different things.

When to use it

  • CloudWatch for logs, metrics and alarms; CloudTrail for AWS control-plane audit.
  • Correlation across run ID, event ID, loan ID, application, batch and workflow execution.
  • Avoid logging task tokens, license keys, credentials or full customer data.

Create through the AWS console / IDE

  1. CloudWatch → Log groups → create /eventflow/lab with a short lab retention. In EKS, install the Amazon CloudWatch Observability add-on with an appropriately permitted role if centralized container logs are desired.
  2. CloudWatch → Metrics → SQS → select eventflow-ingress and ApproximateAgeOfOldestMessage. Create an alarm with a meaningful age threshold and destination.
  3. Use DynamoDB throttling and latency metrics to separate database pressure from Kafka lag. Kafka/consumer lag requires the appropriate MSK/application metrics collection; GUI numbers do not automatically appear in CloudWatch.
  4. CloudTrail → Event history → filter recent stack, role and cluster operations. For durable enterprise audit, configure a reviewed trail/log destination and retention.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.
Command / example
aws logs create-log-group --log-group-name /eventflow/lab
aws logs put-retention-policy --log-group-name /eventflow/lab --retention-in-days 7

aws cloudwatch describe-alarms --alarm-names eventflow-ingress-age

Test this component before continuing

Trace one run from its GUI ID into event state and workflow history. In the lab, prove an alarm action with approved test data/metrics rather than creating an unbounded backlog. Confirm logs have retention and no secrets.

Exit criterion

An alarm definition, useful correlation fields and a known log-shipping path. Local structured logs are implemented; centralized AWS observability installation is a learner deployment step.

package com.eventflow.shared;

import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.ObjectMapper;
import java.util.*;

public final class Json {
    public static final ObjectMapper MAPPER = new ObjectMapper();
    public static String write(Object value) {
        try { return MAPPER.writeValueAsString(value); }
        catch (Exception e) { throw new IllegalArgumentException("Cannot encode JSON", e); }
    }
    public static Map<String,Object> read(String text) {
        try { return MAPPER.readValue(text, new TypeReference<>() {}); }
        catch (Exception e) { throw new IllegalArgumentException("Invalid JSON", e); }
    }
    public static int number(Map<String,Object> m, String key, int fallback) {
        return m.containsKey(key) ? Integer.parseInt(m.get(key).toString()) : fallback;
    }
    public static String text(Map<String,Object> m, String key) { return Objects.toString(m.get(key), ""); }
    @SuppressWarnings("unchecked") public static List<Map<String,Object>> rows(Object value) {
        return (List<Map<String,Object>>) value;
    }
    public static String env(String name, String fallback) { return System.getenv().getOrDefault(name,fallback); }
    public static void log(String component, String message) {
        System.out.println(write(Map.of("time",java.time.Instant.now().toString(),"component",component,"message",message)));
    }
}

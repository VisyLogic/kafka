12 · EKS cluster, managed nodes and private services

EKS supplies the Kubernetes control plane. Managed nodes provide CPU and memory for pods. A Deployment manages process replicas; a Service provides stable in-cluster discovery. Creating an EKS cluster does not automatically deploy application code.

When to use it

  • Multiple containerized services, controlled rollouts and workload scaling.
  • Resource requests/limits and runtime isolation.
  • For a simpler non-Kubernetes workload, evaluate ECS/Fargate rather than assuming EKS is always necessary.

Create through the AWS console / IDE

  1. EKS → Add cluster → Create → Custom configuration. For this managed-node-group lab turn EKS Auto Mode off. Choose a supported standard-support Kubernetes version; do not blindly copy an old version.
  2. Name eventflow, choose EventFlowClusterRole, the EventFlow VPC and both private subnets. Enable private endpoint access and restrict any public API endpoint to the administrator CIDR.
  3. Use API_AND_CONFIG_MAP or the current access-entry mode and grant the operator an access entry. An AWS API permission is different from Kubernetes authorization.
  4. Wait for ACTIVE. Compute → Add node group. Use EventFlowNodeRole, private subnets and a small reviewed instance type. Set min 1, desired 1, max 3. MaxSize alone does not install a node autoscaler.
  5. Configure kubectl and verify a Ready node before deploying workloads.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.
Command / example
# Edit the downloadable cluster request with role, subnet and administrator CIDR values.
aws eks create-cluster --cli-input-json file://examples/eks-cluster.json
aws eks wait cluster-active --name eventflow
aws eks create-access-entry --cluster-name eventflow --principal-arn OPERATOR_ROLE_ARN --type STANDARD
aws eks associate-access-policy --cluster-name eventflow --principal-arn OPERATOR_ROLE_ARN --policy-arn arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy --access-scope type=cluster
aws eks create-nodegroup --cli-input-json file://examples/eks-nodes.json
aws eks wait nodegroup-active --cluster-name eventflow --nodegroup-name learning-workers
aws eks update-kubeconfig --name eventflow --region us-east-1
kubectl get nodes
kubectl auth can-i get pods --all-namespaces

Test this component before continuing

Check cluster ACTIVE, node group ACTIVE, nodes Ready and operator Kubernetes access. If nodes fail to join, inspect private egress, node-role policies and cluster security groups before changing application code.

Exit criterion

A reachable, authorized control plane and Ready managed nodes. No application pods exist until the manifests are applied.

11 · ECR: build once and promote an immutable image

ECR stores the built Java image. The same image runs the console, adapter, sourcing, activity and mock roles. Infrastructure deployment and code deployment are separate operations. A reviewed artifact should be built once, tested, scanned, and promoted by immutable digest.

When to use it

  • Private container distribution to EKS and other runtimes.
  • Image scanning, lifecycle management and release provenance.
  • ECR is not a running service or a source-code repository.

Create through the AWS console / IDE

  1. ECR → Private registry → Repositories → Create repository. Name eventflow, enable immutable tags, and enable the chosen scanning mode.
  2. Review encryption and a lifecycle policy for old unreferenced images. Do not expire a digest still used by an active release.
  3. Build with infrastructure/docker/Dockerfile. The build stage runs Maven tests; the final image contains a JRE and jar, with a non-root user.
  4. Use the repository’s View push commands as a reference, then use your current temporary AWS identity. Do not put a registry password in a file.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.
Command / example
aws ecr create-repository --repository-name eventflow --image-tag-mutability IMMUTABLE --image-scanning-configuration scanOnPush=true
# Bash: replace registry/repository values before running.
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com
docker build -f infrastructure/docker/Dockerfile -t ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com/eventflow:learning-001 .
docker push ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com/eventflow:learning-001
aws ecr describe-images --repository-name eventflow --image-ids imageTag=learning-001

Test this component before continuing

Record the pushed image digest. Confirm Kubernetes can pull it using node/runtime IAM access. If ECR scanning reports a material finding, patch and rebuild a new tag rather than replacing an immutable release.

Exit criterion

An image with a digest, a passing test record and a unique release tag. All five roles reference the same digest.

FROM maven:3.9.9-eclipse-temurin-21 AS build
WORKDIR /build
COPY application/pom.xml ./pom.xml
COPY application/src ./src
COPY gui ./src/main/resources/web
RUN MAVEN_OPTS='-Xmx384m -XX:ActiveProcessorCount=2' mvn -B -q package

FROM eclipse-temurin:21-jre-jammy
RUN groupadd --system eventflow && useradd --system --gid eventflow eventflow
WORKDIR /app
COPY --from=build /build/target/eventflow-1.0.0.jar /app/eventflow.jar
USER eventflow
ENV JAVA_TOOL_OPTIONS="-Xms32m -Xmx192m -XX:ActiveProcessorCount=2"
ENTRYPOINT ["java","-jar","/app/eventflow.jar"]

What to record in your lab notebook

  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

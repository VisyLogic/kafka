M02 · Configure IAM, security groups and the Java client

The Java client needs both network reachability and Kafka data-plane permission. An IAM role assumed by EC2 supplies temporary credentials. The MSK IAM Java library signs authentication; SASL_SSL protects traffic on private port 9098. A successful AWS Console login or kafka:GetBootstrapBrokers permission alone does not grant topic read/write access.

When to use it

  • Learn the difference between AWS control-plane permissions and kafka-cluster data-plane permissions.
  • Use Session Manager rather than opening SSH ports or embedding access keys.
  • Diagnose IAM and networking independently.

Create through the AWS console / IDE

  1. If using the lab stack, open Outputs and find ClientInstance, ClientRole and the two security groups. They are already configured. For the manual path, IAM → Roles → Create role → AWS service EC2. Attach AmazonSSMManagedInstanceCore. Add a lab-only policy equivalent to ClientRole.Policies in the downloaded template, replacing cluster/topic/group ARNs with your account, region and cluster identity.
  2. The data policy permits Connect/DescribeCluster/WriteDataIdempotently on this cluster, CreateTopic/DescribeTopic/ReadData/WriteData on learning.msk.* topics, and DescribeGroup/AlterGroup on msk-learning-* groups. The optional SQS permissions target only the lab queue. Runtime permissions are separate from the operator permissions needed to provision infrastructure.
  3. Manual path: launch an Amazon Linux 2023 x86_64 t3.small client in the same VPC, with the client security group and this instance role. Require IMDSv2. Do not open inbound SSH. The subnet needs SSM connectivity and outbound access for package and Maven downloads.
  4. EC2 → Instances → select the client → Connect → Session Manager → Connect. Wait for SSM registration if necessary. With the lab template the OS tools are not installed automatically; use the commands below. CloudShell is suitable for provisioning, but run private Kafka clients in this EC2 session.
  5. Install Java 21/Maven, then obtain the downloadable source ZIP from the MSK section. Publish the updated learning site first if using its GitHub Pages download URL. Download on EC2 with curl, extract under your home directory and build. Use your own published URL if hosting elsewhere. Never paste long-lived credentials into Java source or HTML.

Test this component before continuing

Confirm Java reports version 21, Maven builds the executable JAR, and running it without arguments prints usage. Resolve a real broker hostname. These checks are prerequisites; M03 tests actual authenticated Kafka access.

Exit criterion

An SSM-managed client can build/run the sample, has a scoped instance role and private connectivity, and contains no static AWS access keys. The supplied source has been compiled locally; AWS connectivity is a lab to execute.

Explain and investigate

A timeout, TLS failure and TopicAuthorizationException point to different boundaries. List the first check for each. If the source ZIP gives 404, verify that downloads/msk-hands-on-source.zip was pushed and Pages finished deploying.

What to record in your lab notebook
  • Account/region, resource IDs and chosen provisioning method.
  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

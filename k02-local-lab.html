K02 · Start your own isolated Kafka lab

Use a separate single-broker KRaft lab to learn without changing EventFlow MSK, consumer offsets or accounting data. This pinned Apache Kafka 4.1.2 image is a teaching example based on Apache documentation, not a request to upgrade the application broker or client. All Kafka CLI commands below run inside the container and connect to its localhost:9092. No host port is published, avoiding listener and port conflicts.

When to use it

  • Learn Kafka before creating MSK or EKS.
  • Practice topic/consumer operations in a disposable environment.
  • KRaft supplies Kafka metadata coordination without a separate ZooKeeper service. This one-broker lab does not demonstrate replication or high availability.

Create through the AWS console / IDE

  1. Start Docker Desktop in Linux-container mode. This optional broker consumes memory in addition to EventFlow; stop the finance services first if the workstation is constrained.
  2. Run docker pull, then docker run below. The container is named kafka-learning; no existing EventFlow container is stopped or changed.
  3. Check its logs and retry the topic-list command until the broker is ready. A started container is not proof of broker readiness.
  4. Use separate PowerShell terminals for interactive producers and consumers in later lessons. The commands also work in Bash.
  5. This lab has no dedicated persistent volume. docker stop/start retains this container’s writable layer; deleting/recreating the container loses the lab data. Never use this storage model for production.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.
Command / example
docker pull apache/kafka:4.1.2
docker run -d --name kafka-learning apache/kafka:4.1.2
docker logs --tail 40 kafka-learning
docker exec kafka-learning /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
# Later sessions, if the same container already exists:
docker start kafka-learning
# Non-destructive stop when finished:
docker stop kafka-learning

Test this component before continuing

List topics successfully. An empty list on a new broker is valid. If the name is already in use, inspect docker ps -a and start the existing lab instead of recreating it.

Exit criterion

One separate lab broker responds to CLI calls. No EventFlow topics, offsets, services or databases have been modified. These new exercises are instructions to perform; they were not executed by the documentation build.

Explain and investigate

Why can these CLI tools use localhost:9092 while a different container generally cannot use that address to reach this broker? Explain network namespaces and advertised listeners.

What to record in your lab notebook

  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.

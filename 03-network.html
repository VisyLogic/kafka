03 · VPC, subnets, routes and security groups

EKS workers and MSK brokers live in a private network. A subnet is an address range in one availability zone; a route table determines next hops; a security group filters allowed traffic. DNS and network reachability are separate from IAM authorization.

When to use it

  • Private databases, Kafka brokers and internal microservices.
  • NAT for controlled outbound traffic such as image/dependency access, or private endpoints where appropriate.
  • Restrict broker traffic to the cluster security group; never expose Kafka to the public internet for a quick fix.

Create through the AWS console / IDE

  1. VPC → Create VPC → VPC and more. Use two availability zones, two public subnets and two private subnets, with DNS support enabled.
  2. For a small lab choose one NAT gateway and note its cost; production resilience usually uses a deliberate per-AZ or endpoint design.
  3. Confirm each private route table has a default route through the NAT and each public route table through the internet gateway. MSK broker traffic remains private.
  4. Record the VPC ID and the two private subnet IDs. Use exactly those same subnets for the EKS node group and MSK.
  5. After EKS creates its cluster security group, allow TCP 9098 from that group into the MSK broker security group for the AWS IAM-authenticated track. LocalStack uses local plaintext broker ports, a different profile.

Create or inspect through CLI

Choose this as an alternative provisioning path; do not create duplicate named resources. Commands are examples for a sandbox and require replacing placeholders. CloudShell examples use Bash; Windows-specific commands are labelled.
Command / example
# The CLI path creates the same network through reviewed infrastructure as code.
aws cloudformation deploy --stack-name eventflow-network --template-file examples/cloudformation/network.yaml
aws cloudformation describe-stacks --stack-name eventflow-network --query "Stacks[0].Outputs"
aws ec2 describe-subnets --subnet-ids SUBNET_A SUBNET_B
aws ec2 describe-route-tables --filters Name=vpc-id,Values=VPC_ID

Test this component before continuing

Verify two different availability zones, the private routes, DNS support, and the MSK security-group source. From the eventual pod/client, test broker connectivity; a successful describe-cluster API call alone is insufficient.

Exit criterion

Two private subnets in different AZs with controlled egress. No public inbound broker rule. The supplied local-network.yaml is only minimal LocalStack metadata and is not the full AWS network.

AWSTemplateFormatVersion: '2010-09-09'
Description: Optional AWS-only two-AZ network for EventFlow. NAT gateway incurs charges.
Resources:
  Vpc:
    Type: AWS::EC2::VPC
    Properties: {CidrBlock: 10.42.0.0/16, EnableDnsSupport: true, EnableDnsHostnames: true, Tags: [{Key: Name, Value: eventflow}]}
  InternetGateway: {Type: 'AWS::EC2::InternetGateway'}
  GatewayAttachment:
    Type: AWS::EC2::VPCGatewayAttachment
    Properties: {VpcId: !Ref Vpc, InternetGatewayId: !Ref InternetGateway}
  PublicA:
    Type: AWS::EC2::Subnet
    Properties: {VpcId: !Ref Vpc, CidrBlock: 10.42.0.0/24, AvailabilityZone: !Select [0, !GetAZs '']}
  PublicB:
    Type: AWS::EC2::Subnet
    Properties: {VpcId: !Ref Vpc, CidrBlock: 10.42.1.0/24, AvailabilityZone: !Select [1, !GetAZs '']}
  PrivateA:
    Type: AWS::EC2::Subnet
    Properties: {VpcId: !Ref Vpc, CidrBlock: 10.42.10.0/24, AvailabilityZone: !Select [0, !GetAZs '']}
  PrivateB:
    Type: AWS::EC2::Subnet
    Properties: {VpcId: !Ref Vpc, CidrBlock: 10.42.11.0/24, AvailabilityZone: !Select [1, !GetAZs '']}
  PublicRoutes:
    Type: AWS::EC2::RouteTable
    Properties: {VpcId: !Ref Vpc}
  InternetRoute:
    Type: AWS::EC2::Route
    DependsOn: GatewayAttachment
    Properties: {RouteTableId: !Ref PublicRoutes, DestinationCidrBlock: 0.0.0.0/0, GatewayId: !Ref InternetGateway}
  PublicARoutes:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties: {SubnetId: !Ref PublicA, RouteTableId: !Ref PublicRoutes}
  PublicBRoutes:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties: {SubnetId: !Ref PublicB, RouteTableId: !Ref PublicRoutes}
  NatAddress:
    Type: AWS::EC2::EIP
    DependsOn: GatewayAttachment
    Properties: {Domain: vpc}
  Nat:
    Type: AWS::EC2::NatGateway
    Properties: {AllocationId: !GetAtt NatAddress.AllocationId, SubnetId: !Ref PublicA}
  PrivateRoutes:
    Type: AWS::EC2::RouteTable
    Properties: {VpcId: !Ref Vpc}
  NatRoute:
    Type: AWS::EC2::Route
    Properties: {RouteTableId: !Ref PrivateRoutes, DestinationCidrBlock: 0.0.0.0/0, NatGatewayId: !Ref Nat}
  PrivateARoutes:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties: {SubnetId: !Ref PrivateA, RouteTableId: !Ref PrivateRoutes}
  PrivateBRoutes:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties: {SubnetId: !Ref PrivateB, RouteTableId: !Ref PrivateRoutes}
Outputs:
  VpcId: {Value: !Ref Vpc}
  PrivateSubnetIds: {Value: !Join [',', [!Ref PrivateA, !Ref PrivateB]]}

Explain and investigate

  • Relevant configuration and why you chose it.
  • The command/test and the observed result, including failures.
  • Recovery action and how you checked the business invariants.
  • Known gaps and the next experiment; exclude secrets and task tokens.
